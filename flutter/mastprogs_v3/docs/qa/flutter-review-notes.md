## FQ-001 — 반투명 어니언 RGBA 업로드 형식

- 상태: Claude 수정 및 회귀 시험 통과. `premultiplyRgba`가 업로드 사본만 변환하고 원본 모델/해시는 유지한다. 브라우저에서도 어니언을 포함한 합성 화면을 확인했다.
- 근거: lib/features/sprite/view/pixel_image_view.dart의 decodeImageFromPixels는 현재 pixels.data(직접 합성한 straight-alpha)를 ui.PixelFormat.rgba8888로 넘긴다. PixelStudioController.stageImage는 tintPixels/composeOver의 반투명 straight-alpha를 포함한다.
- 설치 SDK 근거: Flutter3.41.9 sky_engine/lib/ui/painting.dart의 PixelFormat.rgba8888은 premultiplied alpha를 요구한다.
- 독립 실험: [100,50,25,128]을 그대로 decode 후 rawStraightRgba로 읽으면 [199,100,50,128]. 의도보다 밝아진다. C:/WINDOWS/TEMP/v3_alpha_contract_test.dart 실행 통과.
- 요구 수정: 순수 픽셀 모델/해시/원본 데이터를 바꾸지 말고 ui.Image 업로드 경계에서 사본 RGB를 alpha/255로 사전 곱셈(0/255 원본은 동일)하거나 동등한 정확한 렌더러 변환을 수행. 변환/반투명 readback 회귀 시험과 어니언 화면 확인 필요.
- test/fixtures/renderer-golden.json은 React 원본 어니언18·중심점6 SHA와 SDK 알파 계약을 보존한다. 골든을 수정해 통과시키지 않는다.

## FQ-002 — 장시간 CanvasKit 메모리 오류

- 상태: 앱의 반복 이미지 생성 경로 제거 및 회귀 시험 통과. 네이티브 힙의 정확한 잔류 원인은 확정하지 못했다. 수정 후 기본 자동 연출 10분 56초 이상의 실제 재생에서 모션·팔레트 진행과 콘솔 0을 확인했다. 수동 설정은 최종 빌드에서 별도 검증한다. 99분을 넘긴 재시험과 모든 환경의 안정성을 이 기록만으로 보장하지 않는다.
- 실제 브라우저 `/sprite`, 1440×1100, light, 숲 프리셋·SLSO8 100%, 자동 외곽선 ON·어니언 0.35·셔플/재생 ON.
- 2026-10-04 04:40:44.962 UTC부터 14분 30초 구간은 조작·프레임 진행 및 콘솔 0 확인. 계속 켜 둔 뒤 06:19:51.694 UTC(약 99분)에 CanvasKit `memory access out of bounds` 발생, MakeImage/PictureRecorder 스택 106건.
- 단기 정상 기록을 장기 안정성 통과로 확대하지 않는다. 이미지 생성/해제와 캐시 키를 Claude가 설치 SDK 소스부터 조사한다.
- 기존 이미지 캐시 32개는 4종×28프레임=112개보다 작아 재생마다 새 이미지가 만들어졌다. 자동 연출은 실제 10스타일의 작업 묶음에서 계산한 1,136개, 사람이 색을 고른 뒤에는 128개로 즉시 줄이며 버린 이미지는 해제한다. 하드 상한 1,536개. 자동 연출 여러 주기 이후 및 수동 설정 600틱에서 신규 업로드 0, 살아 있는 이미지 수 일정 검증. 원본 픽셀 해시는 바꾸지 않았다.
- 캐시 적중 또는 원래 프레임으로 돌아간 뒤 오래된 비동기 결과가 화면을 덮던 문제도 실패 재현 테스트 2개로 확인·수정했다.
